## Что нового в 0.26.1

- **Первый публикуемый выпуск линии 0.26.** Пакет 0.26.0 на GitHub не выходил: проверка личных данных перед выпуском
  остановила его на строке авторских прав в лицензии библиотеки проверки телефонов, которая пришла в 0.26.0. Лицензия
  требует сохранять эту строку в поставке, поэтому она внесена в опись разрешённого с причиной. Код магазина тот же,
  что в 0.26.0 — что нового, описано ниже.

### Также в 0.26.0 (отдельно не выходила)

- **Логин отдельно от имени.** Логин — почта или телефон, по которому покупатель зарегистрировался; его нельзя
  изменить (только менеджер). Имя, фамилия и отчество — отдельные поля с подсказками: имя нужно для обращения в
  письмах, фамилия — для доставки, отчество — для оплаты при получении в «Новой Почте». Имя из Telegram, почта или
  номер больше не попадают в поле «Имя». Профиль снова сохраняется у покупателя без фамилии и отчества — раньше
  кнопка «Сохранить» зависала.
- **Телефон по странам магазина.** Номер проверяется по правилам своей страны: длина, код, мобильный ли он.
  Страны выбираются в «Настройки → Локализация» (по умолчанию — страна магазина); номер другой страны витрина и
  сервер отклоняют словами у поля. Занятый номер в профиле — отказ «обратитесь к менеджеру», а не ложное
  «сохранено».
- **Регистрация по телефону через Telegram.** Короткая форма: почта или телефон, пароль, имя и согласие на новости
  (по умолчанию не отмечено). Номер подтверждается в боте покупателей: бот просит поделиться своим контактом и
  присылает код, который вводится на сайте, — ссылкой на бота чужой кабинет не открыть. Если номер уже есть в
  магазине (заказ без регистрации, площадка), пароль из формы на него не ставится: владелец номера входит через
  Telegram и задаёт пароль в кабинете. После входа бот пишет «Выполнен вход в кабинет» с устройством и кнопкой
  «Это не я» — она закрывает все сеансы и снимает пароль. Согласие на рассылку при регистрации по телефону не
  ставится: его включают в кабинете. Номер, вписанный самим покупателем, не притягивает чужие заказы, в том числе
  с площадок.
- **Оформление заказа.** Имя и фамилия получателя обязательны всегда, при наложенном платеже — и отчество
  (требование «Нової Пошти»); вошедшему они подставляются из профиля. Поле с ошибкой получает фокус.
- **Уведомления в Telegram.** Подключить Telegram, прислать пробное сообщение и отключить можно прямо на экране
  «Уведомления»; каждую тему можно получать в Telegram, тихие часы не будят ночью (подтверждение и отмена заказа
  приходят всегда). Отдельный флажок «заказы в Telegram» заменён настройкой темы — один выбор вместо двух.
- **Деньги.** Оплата картой считается по факту поступления: частичная оплата не запускает следствия «оплачен»,
  повторный ответ банка не начисляет второй раз, гостю приходит ссылка оплаты.

Что нужно знать при обновлении: существующим кабинетам логин выставляется сам — почта, если она есть, иначе
телефон. Номера в базе приводятся к единому виду и получают ключ поиска; совпадающие номера разных покупателей не
сливаются — номера таких карточек записываются в журнал приложения.

## Почему файлов нет в списке вверху страницы

Список вверху (`LICENSE`, `README.md`) — это сам репозиторий, то есть тексты. Пакеты весят десятки мегабайт и у каждой версии свои, поэтому GitHub хранит их отдельно — как вложения к письму — на странице выпуска ([версия 0.26.1](https://github.com/1s83gnsh/shpura-releases/releases/tag/v0.26.1), блок «Assets» внизу). Ссылки выше ведут прямо на эти вложения: нажали — и браузер скачивает файл. Все версии — на странице [Releases](https://github.com/1s83gnsh/shpura-releases/releases).

## Можно ли доверять файлам

Каждый выпуск подписан ключом издателя (Ed25519): сайт ставит пакет, только если подпись верна, а в подписанной описи `shpura-release.json` записан SHA-256 каждого файла. Подменить пакет, даже получив доступ к GitHub, нельзя. Перед установкой сайт сам снимает копию базы и при сбое возвращает прежнюю версию; товары, заказы, покупатели, настройки и фото обновление не меняет.
