## Что нового в 0.24.0

- **Раздел «Система» находится сам.** Владелец открыл экран обновления только по ссылке из чата: пункт меню
  назывался «Система / интеграции / cron / журналы» и обрезался, а мастер обновления жил ссылкой внизу длинной
  страницы. Теперь в меню один пункт «Система» с вкладками «Обзор · Обновление · Резервные копии · Готовность к
  запуску»; «Обзор» — четыре плитки «сейчас» (версия, копия базы, регламенты, состояние), каждая ведёт в свою
  вкладку. Номер версии внизу боковой панели — ссылка на обновление с пометкой «есть обновление»; на главной админки
  появляется карточка, только когда есть что делать (новая версия, прерванная установка, магазин закрыт после
  неудачной установки). У каждой вкладки — строка «что это» и справка в шторке. Подписи групп меню («Управление
  системой», «Продажи и продвижение») больше не обрезаются многоточием, а переносятся на вторую строку.
- **Обновление — мастер по шагам.** Сверху одна фраза «что сейчас» и одна кнопка по ситуации; ниже шаги «Откуда →
  Проверка → Установка → Готово», одинаковые для GitHub, ссылки и файла ZIP. Проверка идёт сама и говорит словами;
  перед установкой сказано, что магазин закроется на время, копия базы сделается сама, при сбое всё вернётся. На шаге
  «Готово» — было → стало, сколько файлов заменено, что нового и откат с объяснением. Под мастером — «Автообновление»
  (режим и работает ли проверка: когда последняя и следующая, настроен ли cron), «История обновлений» (дата, было →
  стало, способ, кто, итог) и «Файлы сайта».
- **«Восстановить из выпуска» вместо FTP.** Если на хостинге пропал файл, которого пакет не везёт, сайт сам берёт
  подписанный полный пакет своей версии с GitHub и кладёт только недостающие файлы, ничего существующего не
  перезаписывая. Пока идёт восстановление, установка и ночное автообновление ждут, и наоборот.
- **Ложная карточка «Не хватает файлов сайта» после успешной установки ушла.** Экран проверял файлы только при
  открытии и показывал проверку, сделанную ещё на старой версии; теперь перепроверяет после установки, отката и
  «Открыть магазин». А сервер после установки больше не прячет действительно пропавшие файлы последнего пакета.
- **Ссылка на вариант товара и метки рекламы больше не теряются при переходе.** «/product/N?variant=…», «/category/N»,
  старые адреса OpenCart и «?route=…» уводили на человеческий адрес без строки запроса: ссылка на выбранный цвет
  открывала первый, «gclid» и «utm_*» объявлений Google Ads пропадали. Проверка `storefront_redirect_keeps_query`.
- Проверки: `update_history`, `update_restore_from_release`, `update_check_service` (П.14), `update_download_job`,
  `update_integrity_friendly` (Д.9), сценарии мастера и раздела «Система» на 360/768/1366; независимое ревью и
  повторное ревью исправлений (Critical и Important — 0).

## Почему файлов нет в списке вверху страницы

Список вверху (`LICENSE`, `README.md`) — это сам репозиторий, то есть тексты. Пакеты весят десятки мегабайт и у каждой версии свои, поэтому GitHub хранит их отдельно — как вложения к письму — на странице выпуска ([версия 0.24.0](https://github.com/1s83gnsh/shpura-releases/releases/tag/v0.24.0), блок «Assets» внизу). Ссылки выше ведут прямо на эти вложения: нажали — и браузер скачивает файл. Все версии — на странице [Releases](https://github.com/1s83gnsh/shpura-releases/releases).

## Можно ли доверять файлам

Каждый выпуск подписан ключом издателя (Ed25519): сайт ставит пакет, только если подпись верна, а в подписанной описи `shpura-release.json` записан SHA-256 каждого файла. Подменить пакет, даже получив доступ к GitHub, нельзя. Перед установкой сайт сам снимает копию базы и при сбое возвращает прежнюю версию; товары, заказы, покупатели, настройки и фото обновление не меняет.
