## Что нового в 0.26.2

- **Обновление больше не оставляет сайт с ошибкой 500 посреди установки.** На демо установка 0.25.0 → 0.26.1
  остановилась на 65 %, и после перезагрузки сайт не открывался совсем — не работали ни «Продолжить», ни откат.
  Причина: файлы заменялись по алфавиту, и опись автозагрузки ложилась раньше новой библиотеки, которую она
  требует. Теперь пакет обновления кладёт сначала защиту запуска, потом новые файлы, потом изменённые, а файлы,
  через которые PHP запускается на каждом запросе, — последними. Файлы автозагрузки ставятся одним шагом, имя её
  класса закреплено и больше не меняется от выпуска к выпуску.
- **Сайт сам поднимается, если замена файлов всё-таки сломала запуск.** Пока идёт установка, запрос, который не
  смог запуститься, возвращает файлы из копии, сделанной перед обновлением. База в этот момент ещё не менялась.
  Магазин открывается на прежней версии, посетитель вместо 500 видит «идёт обновление», а на экране «Система →
  Обновление» кнопка «Продолжить» завершает отмену и записывает её в историю. «Продолжить откат» после неудачной
  установки больше не отвечает «действие недоступно».

- **Картинки разделов — без кириллицы в имени файла.** Картинка « по номерам_160_160.jpg» после распаковки архива
  панелью хостинга получала битое имя рядом с правильным, а её копии в папке обновлений панель не могла удалить.
  Теперь она называется `po-nomeram-160-160.jpg`, «unnamed (1).jpg» — `unnamed-1.jpg`. Обновление само переименует
  файлы на сайте, поправит пути разделов и удалит копии с битыми именами — только те, что побайтно совпадают с
  картинкой раздела. Загрузка нового пакета обновления убирает из папки обновлений всё, что осталось от прошлых
  установок; копия для ручного отката неудачного обновления сохраняется. Сборка выпуска не пропустит картинку с
  кириллицей, пробелом или скобками в имени, а загрузка картинок разделов со старого магазина кладёт их сразу под
  латинскими именами.

Что нужно знать при обновлении: защита запуска ставится первым файлом пакета, поэтому работает уже при
обновлении до 0.26.2. Дальше по решению владельца установка переходит на схему «рядом + переключение» с кнопкой
«Остановить и вернуть как было» на каждом этапе (`docs/plans/2026-10-27-obnovlenie-ryadom-i-pereklyuchenie.md`).

## Почему файлов нет в списке вверху страницы

Список вверху (`LICENSE`, `README.md`) — это сам репозиторий, то есть тексты. Пакеты весят десятки мегабайт и у каждой версии свои, поэтому GitHub хранит их отдельно — как вложения к письму — на странице выпуска ([версия 0.26.2](https://github.com/1s83gnsh/shpura-releases/releases/tag/v0.26.2), блок «Assets» внизу). Ссылки выше ведут прямо на эти вложения: нажали — и браузер скачивает файл. Все версии — на странице [Releases](https://github.com/1s83gnsh/shpura-releases/releases).

## Можно ли доверять файлам

Каждый выпуск подписан ключом издателя (Ed25519): сайт ставит пакет, только если подпись верна, а в подписанной описи `shpura-release.json` записан SHA-256 каждого файла. Подменить пакет, даже получив доступ к GitHub, нельзя. Перед установкой сайт сам снимает копию базы и при сбое возвращает прежнюю версию; товары, заказы, покупатели, настройки и фото обновление не меняет.
