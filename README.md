## Что нового в 0.23.3

- **На страницах витрины снова один `canonical`.** С тех пор как сервер начал отдавать готовый `<head>` (заголовок,
  адреса, разметка для поисковиков), на каждой странице оказывалось по два `canonical`, по две пары `hreflang`, двойные
  `og:*`, `twitter:*` и JSON-LD: служба SEO приложения при показе страницы снимала только свои помеченные теги и ставила
  свои, а серверные пометки не несли. Два `canonical` поисковик вправе не учесть оба. Теперь сервер помечает свои SEO-теги
  той же пометкой `data-sf-seo`, и приложение заменяет их, а не добавляет вторые. Найдено сценарием страницы бренда при
  прогоне соседей правки шапки. Проверка `storefront_head_seo_owned` (слом доказан), сценарии бренда, языка и уточнения
  товара зелёные; на живом сервере после загрузки страниц бренда, раздела и товара — ровно один `canonical`.

### Также в 0.23.2 (отдельно не выходила)

- **Шапка витрины на телефоне: лупа стоит в ряду правых значков, логотип не уходит под неё.** Владелец прислал снимок
  демо на телефоне: значок поиска прилип к логотипу. Замер показал причину глубже, чем видно глазом: ниже 768 точек
  справа стоят пять значков по 44 точки (поиск, телефон, язык, корзина, меню), логотипу оставалось 84–136 точек, а
  рисовался он шириной до 40 % экрана и залезал под лупу; лишняя пустая колонка сетки добавляла зазор. Теперь сетка
  из трёх частей (логотип, лупа, значки), лупа идёт тем же шагом, что остальные значки, логотип вписывается в свою
  часть с сохранением пропорций. Проверка `e2e/storefront-header-phone-actions.spec.ts` на ширинах 320–767 (до правки
  красная на всех семи), соседние сценарии поиска (82) и меню зелёные, снимки 360, 390 и 412 осмотрены.
- **README репозитория выпусков** ведёт прямо к файлам последнего выпуска: на GitHub пакеты лежат на странице
  выпуска (блок «Assets»), а не в списке файлов.

## Почему файлов нет в списке вверху страницы

Список вверху (`LICENSE`, `README.md`) — это сам репозиторий, то есть тексты. Пакеты весят десятки мегабайт и у каждой версии свои, поэтому GitHub хранит их отдельно — как вложения к письму — на странице выпуска ([версия 0.23.3](https://github.com/1s83gnsh/shpura-releases/releases/tag/v0.23.3), блок «Assets» внизу). Ссылки выше ведут прямо на эти вложения: нажали — и браузер скачивает файл. Все версии — на странице [Releases](https://github.com/1s83gnsh/shpura-releases/releases).

## Можно ли доверять файлам

Каждый выпуск подписан ключом издателя (Ed25519): сайт ставит пакет, только если подпись верна, а в подписанной описи `shpura-release.json` записан SHA-256 каждого файла. Подменить пакет, даже получив доступ к GitHub, нельзя. Перед установкой сайт сам снимает копию базы и при сбое возвращает прежнюю версию; товары, заказы, покупатели, настройки и фото обновление не меняет.
